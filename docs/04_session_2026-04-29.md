## 2. VPS 인프라 — Oracle Free Tier 부터 relay 까지

### 가입·VM 생성

**시도 1**: A1.Flex (ARM, 4 OCPU + 24 GB RAM) → **Out of capacity** (인기 많음)
**최종**: VM.Standard.E2.1.Micro (x86, 1 OCPU + 1 GB) — relay 용으론 충분
**리전**: South Korea North (Chuncheon, ap-chuncheon-1)

### Network 셋업 — 함정 두 개

**함정 1 — inline VCN 생성의 한계**
Compute create 폼 안에서 "Create new VCN + Public Subnet" 옵션 선택했더니 Public IP 토글이 회색이라 클릭 불가. Subnet IPv4 prefixes 드롭다운도 비활성. 인라인 모드의 옵션 제한 문제.

**해결**: VM 생성 후 **VNIC IP administration → Add public IP (Ephemeral)** 로 사후 부여. 또는 처음부터 VCN Wizard 로 분리 생성하는 게 더 깔끔.

**함정 2 — SSH key 미스매치**
첫 VM 생성 시 SSH key 붙여넣기 시 일부 누락 → `Permission denied (publickey)`.
**해결**: Terminate 후 재생성. VCN/Subnet 은 재사용. `cat ~/.ssh/id_ed25519.pub | pbcopy` 로 클립보드 통째 복사 후 붙여넣기.

**함정 3 — 2층 방화벽**
Tailscale IP 로는 닿는데 Public IP 로는 안 닿음. 원인:
1. **Oracle Security List** (cloud level) — 8765 ingress rule 누락
2. **VPS iptables** (host level) — Oracle Ubuntu 이미지 기본 REJECT 룰

**해결**:
```bash
# host iptables (REJECT 룰 위에 8765 ACCEPT 삽입)
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 8765 -j ACCEPT
sudo netfilter-persistent save

# Oracle Security List → Default → + Add Ingress Rule (TCP 8765)
```
